# React Events and Input Practice

This small React project demonstrates three basic ideas:

- **Events:** React can run a function when someone clicks a button or types in a field.
- **State:** A component can remember a value and update the page when that value changes.
- **Controlled input:** The text box displays the value in state, and typing updates that state.

You only need basic JavaScript to follow along. The React parts are explained below in plain English.

## What the app does

The page has a **ShowAlert** button, a text box, and a **ClearAll** button.

1. Click **ShowAlert** to see a browser message that says `Hello React`.
2. Type in the text box. The text appears both in the box and as a large heading below it.
3. Click **ClearAll** to empty the box and remove the heading text.

## How the code works

The main page is in [`src/App.jsx`](./src/App.jsx).

### Remembering the text with state

Near the top of `App`, this line creates a value React can remember:

```jsx
const [text, setText] = useState("");
```

- `text` is the current value. It starts as an empty string (`""`).
- `setText` is the function used to change `text`.
- `useState` is a React Hook: a special React function that lets a component remember information.

When `setText` changes the value, React updates the page to show the new value.

### Responding to clicks

`handleClick` shows the browser alert. The **ShowAlert** button has `onClick={handleClick}`, which gives React the function to run when the button is clicked.

`handleClear` calls `setText("")`. This resets the text to an empty string. The **ClearAll** button runs this function when clicked.

Notice that the button uses `handleClick`, not `handleClick()`. Passing the function tells React to run it later, after a click. Adding parentheses would call the function immediately while React is displaying the page.

### Keeping the input and state in sync

The input uses `value={text}`, so its displayed text comes from the `text` state. Its `onChange={handleChange}` tells React to run `handleChange` whenever the input changes.

The browser gives `handleChange` an event object. In this code, it is called `p`:

```jsx
setText(p.target.value);
```

- `p.target` means the input element that changed.
- `p.target.value` is the text currently in that input.
- `setText(...)` saves that text in state.

Together, `value={text}` and `onChange={handleChange}` make the input a **controlled input**. State holds the current text, and the input always displays it.

The heading `<h1>{text}</h1>` also displays the current state value. Curly braces inside JSX let you put a JavaScript value into the page.

## What each project file is for

| File or folder | What it is used for |
| --- | --- |
| [`index.html`](./index.html) | The starting HTML page. It contains the `root` element where React puts the app. |
| [`src/main.jsx`](./src/main.jsx) | Starts React, finds the `root` element, and displays the `App` component inside it. |
| [`src/App.jsx`](./src/App.jsx) | Defines the app's buttons, text input, state, and event-handler functions. |
| [`src/index.css`](./src/index.css) | The place for CSS rules that style the whole page. |
| [`src/App.css`](./src/App.css) | The place for CSS rules specific to the `App` component. |
| [`package.json`](./package.json) | Lists project packages and commands such as `dev`, `build`, and `lint`. |
| `node_modules/` | Holds packages installed for the project. It is generated by npm and should not be edited by hand. |
| `dist/` | Holds the production files generated by the build command. It is generated and should not be edited by hand. |

## How the files connect

1. The browser opens `index.html`.
2. `index.html` loads `src/main.jsx`.
3. `main.jsx` renders the `App` component from `src/App.jsx` inside the page's `root` element.
4. `App.jsx` returns the buttons, input, and heading that you see.

## Run the project

Open a terminal in the project folder (the folder containing `package.json`) and run:

```sh
npm install
npm run dev
```

Open the local address printed in the terminal to view the app. Keep the terminal running while you use the development page.

## Useful project commands

Run these commands from the project folder:

| Command | What it does |
| --- | --- |
| `npm run dev` | Starts the local development server. |
| `npm run build` | Checks and builds the app for production in `dist/`. |
| `npm run preview` | Previews the production build locally. Run `npm run build` first. |
| `npm run lint` | Checks the project files for common code problems. |

## Quick reminder

- `onClick` and `onChange` connect user actions to handler functions.
- Pass a handler like `onClick={handleClick}`; do not call it like `onClick={handleClick()}`.
- `useState` stores a value that can change.
- Use the state setter, such as `setText`, to update state.
- A controlled input uses state for `value` and updates it with `onChange`.
